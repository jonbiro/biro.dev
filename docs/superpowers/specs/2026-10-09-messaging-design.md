# Messaging & structure: design

Status: design approved in conversation (sections 1–4), awaiting spec review
Date: 2026-10-09
Branch: `claude/messaging` (stacked on `claude/foundation`)
Program: sub-project 2 of 5 (Foundation → **Messaging & structure** → Visual redesign → Credibility → Demo upgrade)

## Why

The site is built for startup-program reviewers first, with a clear, welcoming path for people seeking help. Today it is honest but hard to scan:

- 115 separately worded status hedges ("pre-release", "not a released application", "capabilities are still being developed", …) repeat what each page has already said.
- `/products/` has 11 sections. The eight concept cards alone are 1,234 words, mostly duplicating the dedicated product pages.
- Home tells an eight-section story but never shows what exists today, what comes next, or who the founder is beyond one sentence. The site has no founder profile links.

## Decisions (from the brainstorming session)

| Topic | Decision |
| --- | --- |
| Main reader | Reviewers first, with a clear path for people seeking help |
| Product positioning | **Flagship-first, untiered.** AddvancedFocus leads. The other eight appear as one equal group of concepts. No priority order is published |
| Founder information | **Profile links only.** GitHub now (`https://github.com/jonbiro`, verified as Jonathan Biro's public profile). LinkedIn later, through a configuration slot left off by default |
| Copy source | Existing editorial content, condensed and reorganized. Nothing new is invented |

## Non-goals

- No visual redesign (sub-project 3). New markup uses existing components and classes. Any new class gets a minimal rule in the matching `startup/styles/` partial.
- No new founder biography, roles, history, photo, metrics, customers, funding, partners, dates, prices, platforms, or AI provider.
- No change to routes, redirects, Netlify configuration, the demo's behavior (`concept-model.js`, `site.js`), or the accessibility statement's content except where listed below.

## 1. Status system and voice

**Status labels.** Exactly three, shown as a `pill`, once per object they describe:

| Label | Applies to |
| --- | --- |
| `Working demo` | The scripted AddvancedFocus interactive concept on `/addvancedfocus/#concept-demo` |
| `In development` | The AddvancedFocus application |
| `Concept` | CareBridge, StoryReady, ClearCue, PlainPath, StepAble, SayAble, SensoryScout, OpenCall |

**"Where things stand" block.** One shared component, generated by a single function in `generate.py` so every use stays identical. It replaces the Products "readiness" section and appears on Home (compact variant), Products and AddvancedFocus. Three columns:

- **Built and working:** the interactive concept (three everyday situations, two energy levels, three illustrative steps each; two- and five-minute sessions; pause with a return note of up to 240 characters; stop without marking complete; undo), this website, and its accessibility statement.
- **In development:** the AddvancedFocus application, covering AI-assisted task initiation and planning, flexible routines, and household coordination.
- **Not yet decided:** public launch date, pricing, supported platforms, AI provider, and data practices. This is the **only** place these are listed.

The Products variant adds the existing three development stages (*Make the interaction tangible → Add useful intelligence → Clarify the full experience*) under the columns, headed "How we're building it".

**Sitewide footer line.** "Biro.dev is pre-release. Concepts and artwork are illustrative, not released apps."

**Disclaimers that stay:**
- Mockup and logo-family captions (an image could be mistaken for a screenshot).
- Each product page's single "When can I use …?" FAQ answer.
- The AddvancedFocus "Is AddvancedFocus a medical product?" answer.
- The Mission privacy note.
- The accessibility statement's "not yet verified" content.

**Voice rules:**
- What exists: plain present tense ("The demo lets you pause and leave yourself a note").
- What is planned: "we're building …" or "designed to …".
- What is undecided: only in "Not yet decided".
- Never "will" for an undecided capability.
- No claim may become stronger than its source sentence.

## 5. Configuration

`startup/site-config.json` gains:

```json
"profiles": {
  "github": "https://github.com/jonbiro",
  "linkedin": ""
}
```

`generate.py` renders a profile link only when its URL is non-empty and starts with `https://`. Adding LinkedIn later is a one-line change.

Each profile link opens in the same tab, with visible text naming the service ("GitHub"). It has no icon-only form, and it carries `rel="me"`.

## Acceptance criteria

1. Every page keeps exactly one `h1`, no skipped heading levels, and labeled landmarks, and passes the Foundation QA `npm test` (axe WCAG 2.2 AA, structure, keyboard demo) in Chromium and WebKit.
2. The phrases "not a released", "not yet publicly available", "release timing", "have not been announced" and "pre-release" appear sitewide only in the places listed under "Disclaimers that stay", the "Where things stand" block, the footer line, and the Home hero micro line. A plan task adds a grep check that enforces this list.
3. `/products/` main content is under 1,200 words. Home has the seven sections in the order above.
4. Every factual statement in the new copy is either a verbatim or condensed sentence from the current site, or a description of the demo's behavior verified against `startup/check-concept.cjs` and `site.js`. The pull request includes a before/after copy table for every changed sentence.
5. A `compare` report (Foundation toolkit) is attached to the pull request, listing the changed pages. No page outside the scope above changes.
6. The demo's behavior is unchanged: `node check-concept.cjs` and the QA `demo` tests pass without modification.
7. `site-config.json` with an empty `linkedin` renders no LinkedIn link. A valid `https://` URL renders one in all three places.
