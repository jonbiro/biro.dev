A little context

About

QA Automation Engineer / SDET in Los Angeles with a full-stack background and a systems mindset.

I design automation around release risk: critical user journeys, explicit test data, fast feedback, and failures that tell the next person what to do.

  • Start with risk: map critical journeys and failure modes before choosing what to automate.
  • Make red builds useful: attach the logs, traces, screenshots, and data needed to act.
  • Use full-stack context to improve testability across browser, services, data, and CI.
  • Keep smoke suites small and deterministic; grow coverage where it improves release decisions.

UI + Mobile Automation

Stable selectors, reusable fixtures, cross-browser coverage, and maintainable flows with Playwright, Selenium, Cypress, and Appium.

API + Integration

Contract-aware API coverage, explicit test data, useful logs, and checks that fail for one understandable reason.

CI Quality Systems

Parallel suites, sensible retries, failure artifacts, and quality gates that turn a red build into a quick decision.
